# 操作系统课程设计报告初稿：进程调度的模拟实现

## 1. 课设题目

进程调度的模拟实现。

## 2. 课设目的

本课程设计旨在通过编写图形化进程调度模拟程序，加深对操作系统进程调度原理的理解。通过实现 FCFS、SJF、SRTF、Priority、Preemptive Priority 和 RR 等调度算法，掌握进程到达时间、服务时间、剩余时间、开始时间、完成时间、周转时间、带权周转时间等核心概念，并能够使用甘特图直观展示调度过程。

## 3. 需求分析

系统需要提供图形化操作界面，用户可以输入多个进程的信息，包括进程名、到达时间、服务时间和优先级。用户选择调度算法后，系统应根据算法规则计算调度结果，并展示每个进程的开始时间、完成时间、周转时间和带权周转时间。

系统还需要绘制甘特图，使用户能够直观看到 CPU 在不同时间段运行的进程。对于 SRTF、抢占式优先级调度和 RR 时间片轮转算法，同一个进程可能多次获得 CPU，因此甘特图中允许同一进程出现多个运行片段。为避免图形过碎，连续执行同一进程的相邻时间片可以合并成一个甘特图片段。

## 4. 系统总体设计

系统采用 C++17 + Win32 API + GDI 实现，整体分为两个主要模块：

1. **调度算法模块**：负责保存进程数据并计算不同算法下的调度结果。
2. **图形界面模块**：负责创建窗口控件、响应按钮事件、显示列表结果、显示算法说明以及绘制甘特图。

程序代码集中在 `src/main.cpp` 中，便于课程设计提交和检查。界面使用 Win32 API 创建输入框、按钮、下拉框、算法说明区和列表控件，甘特图使用 GDI 绘制矩形、文字和边框。

## 5. 数据结构设计

程序中主要使用三个结构体：

### 5.1 Process 结构体

`Process` 用于描述一个进程，字段包括：

- `name`：进程名。
- `arrivalTime`：到达时间。
- `burstTime`：服务时间。
- `remainingTime`：剩余运行时间，主要用于抢占式算法和 RR 算法。
- `priority`：优先级，数字越小优先级越高。
- `startTime`：第一次获得 CPU 的时间。
- `finishTime`：完成时间。
- `turnaroundTime`：周转时间。
- `weightedTurnaroundTime`：带权周转时间。
- `inputOrder`：输入顺序，用于同分情况下保证结果稳定。

### 5.2 GanttBlock 结构体

`GanttBlock` 用于描述甘特图中的一个运行片段，字段包括：

- `processName`：运行进程名。
- `startTime`：片段开始时间。
- `endTime`：片段结束时间。

### 5.3 ScheduleResult 结构体

`ScheduleResult` 用于保存一次调度的整体结果，包括：

- 调度后的进程列表。
- 甘特图运行片段列表。
- 平均周转时间。
- 平均带权周转时间。
- 调度顺序字符串。

## 6. 调度算法设计

### 6.1 FCFS 先来先服务算法思想

FCFS 是非抢占式算法，按照进程到达时间从早到晚调度进程。到达时间相同则按照输入顺序执行。若 CPU 空闲，则系统时间推进到下一个进程的到达时间。每个进程一旦开始执行，会一直运行到完成。

### 6.2 SJF 非抢占式短作业优先算法思想

SJF 非抢占式算法在 CPU 空闲时，从所有已经到达且尚未完成的进程中选择服务时间最短的进程执行。若服务时间相同，则到达时间早者优先；若仍相同，则输入顺序早者优先。该算法不允许新到达的短作业打断正在运行的进程。

### 6.3 SRTF 抢占式短作业优先算法思想

SRTF 是 SJF 的抢占式版本，也称最短剩余时间优先。系统按时间单位推进，每个时间单位都检查当前已经到达且尚未完成的进程，选择剩余运行时间最短者执行。如果新到达进程的剩余时间比当前进程更短，则当前进程会被抢占，新进程先运行。若剩余时间相同，则到达时间早者优先；若仍相同，则输入顺序早者优先。

### 6.4 Priority 非抢占式优先级调度算法思想

Priority 非抢占式算法规定优先级数字越小优先级越高。CPU 空闲时，从已经到达且尚未完成的进程中选择优先级最高的进程执行。若优先级相同，则到达时间早者优先；若仍相同，则输入顺序早者优先。进程一旦开始运行，就不允许被新到达的高优先级进程打断。

### 6.5 Preemptive Priority 抢占式优先级调度算法思想

Preemptive Priority 是优先级调度的抢占式版本。系统按时间单位推进，每个时间单位选择当前已经到达且尚未完成的最高优先级进程执行。如果新到达进程的优先级高于当前进程，则可以抢占当前进程。若优先级相同，则剩余时间短者优先；若仍相同，则到达时间早者优先；若仍相同，则输入顺序早者优先。

### 6.6 RR 时间片轮转算法思想

RR 算法使用就绪队列维护已经到达的进程。进程按照到达时间进入队列，到达时间相同则按照输入顺序入队。每次从队首取出一个进程运行一个时间片；若进程剩余服务时间小于时间片，则只运行剩余时间。运行结束后，如果进程还未完成，则重新进入队尾；如果已经完成，则记录完成时间。

### 6.7 抢占式与非抢占式的区别

- **非抢占式**：进程一旦获得 CPU，就一直运行到完成或主动释放 CPU，调度器不会因为新进程到达而强制中断当前进程。
- **抢占式**：当更符合调度条件的新进程到达时，调度器可以中断当前进程，让新进程先运行。抢占式算法能够更及时地响应短作业或高优先级作业，但调度过程更复杂。

## 7. 图形界面设计

界面使用 Win32 API 创建，主窗口标题为“进程调度模拟系统”。窗口中包含以下控件：

- 进程名输入框。
- 到达时间输入框。
- 服务时间输入框。
- 优先级输入框。
- 添加进程按钮。
- 删除选中进程按钮。
- 清空进程按钮。
- 调度算法选择框，包含 6 种算法。
- RR 时间片输入框。
- 开始调度按钮。
- 算法说明区域。
- 输入进程信息列表。
- 调度结果列表。
- 甘特图绘制区域。

甘特图绘制区域使用 GDI 完成。每个进程运行片段使用矩形表示，矩形中显示进程名，矩形下方显示开始时间和结束时间。不同进程使用不同颜色，便于观察调度过程。

## 8. 运行结果说明

测试数据如下：

| 进程名 | 到达时间 | 服务时间 | 优先级 |
| ------ | -------- | -------- | ------ |
| P1     | 0        | 4        | 3      |
| P2     | 1        | 3        | 1      |
| P3     | 2        | 5        | 4      |
| P4     | 3        | 2        | 2      |
| P5     | 4        | 4        | 5      |

运行时依次添加上述进程，选择不同算法并点击“开始调度”，系统会在右侧结果列表中显示每个进程的进程名、到达时间、服务时间、优先级、开始时间、完成时间、周转时间和带权周转时间，并在下方显示平均周转时间、平均带权周转时间、调度顺序以及甘特图。

以 SRTF 为例，如果一个新到达进程的剩余运行时间比当前运行进程更短，则会发生抢占；以 Preemptive Priority 为例，如果一个新到达进程优先级更高，则会抢占当前进程；以 RR 为例，若时间片设置为 2，则每个进程最多连续运行 2 个时间单位，未完成的进程重新进入就绪队列。

## 9. 课程设计总结

通过本次课程设计，完成了一个基于 C++17、Win32 API 和 GDI 的进程调度模拟系统。项目实现了进程信息录入、进程列表管理、六种经典调度算法、调度结果统计、算法说明展示和甘特图可视化展示。

本设计避免使用 Qt、MFC、EasyX 等额外图形库，降低了环境配置复杂度，更适合在 Windows + VS Code + MinGW 环境中编译运行。通过该项目，可以更加直观地理解抢占式和非抢占式调度算法的执行过程和性能差异。
